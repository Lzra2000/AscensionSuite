What drives the layout

  • Tabs, not a second window. One /asuite frame keeps the DialogFrame gold chrome and the existing drag/close behaviour; the Assists tab is the old overlay, unchanged.
  • The list is the hero. Eight visible 28px rows on a FauxScrollFrame instead of the fixed two-row 8×2 icon grid, so a wishlist built by Alt + right-clicking through the book is readable rather than counted in a +N more line.
  • Icon / name / tooltip come from AscensionAPI 1:1 and fall back to GetSpellInfo. An id the client cannot resolve still lists — greyed, question-mark icon — rather than being rejected, because an unresolvable id in one mode can resolve in another.
  • The Desired badge is live, not stored. It is one IsDesiredID probe per visible row, so it tells the truth even after the player edits Desired in Ascension's own window.
  • Push to Desired is the only Wildcard-gated control. Everything else works anywhere, which is the whole point of the change.
